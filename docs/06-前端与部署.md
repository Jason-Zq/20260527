### 3. 前端轮询模型
- 提交批次后前端定时调 `pollBusinessBatch(batchId)`（business 模式）或 `pollArchiveDetect(batchId)`（快速检测兜底），直到 `status=done`。
- 主进程内存态 `_batch_status` 是轮询 fast-path，DB 是权威。

### 4. 前端与后端耦合点（重构必须保持的契约）
- 所有响应字段名（如 `verdict`/`overall_verdict`/`match_score`/`is_reused`/`files[]`）。
- 轮询语义（`status` 取值、done 判定）。
- 静态资源路径 `/uploads/*`（OCR PNG、拆分/模板产物）。
- 错误码语义（详见 [02](02-API接口清单.md) 通用约定）。

## 二、部署（Linux 生产）

**永久部署平台：Alibaba Cloud Linux 3 / CentOS 8+ ECS**（Windows 仅开发）。方案在 `deploy/linux/`。

### 1. 部署架构
```text
             nginx (80/443)
             ├─ /            → frontend/dist（静态）
             ├─ /api/        → 127.0.0.1:8000（反代 .NET / 现 FastAPI）
             ├─ /uploads/    → output/（静态直发）
             └─ /healthz     → :8000/api/healthz
                    │
             ┌──────▼───────────────────────┐
             │ doc-review.service (systemd)  │  主进程 uvicorn --workers=1
             │  Wants=doc-review-worker@1    │
             └──────┬───────────────────────┘
             ┌──────▼───────────────────────┐
             │ doc-review-worker@N.service   │  OCR worker（可多起 @1/@2/…）
             └───────────────────────────────┘
                    │
             PostgreSQL（DATABASE_URL 注入）
```

### 2. systemd
- **`doc-review.service`**：主进程。`ExecStart=uvicorn main:app --host 127.0.0.1 --port 8000 --workers 1`。`Wants=doc-review-worker@1.service`（启动时拉起 1 个 worker，但 `restart doc-review` 不重启已跑 worker）。MemoryMax=2G。`--workers=1 不可改`（内存态缓存）。
- **`doc-review-worker@.service`**（模板）：`ExecStart=python -m worker_runner --worker-id worker-%i`。`Restart=always`。`KillSignal=SIGTERM` + `TimeoutStopSec=180`（优雅退出）。MemoryMax=2G。改 OCR 代码要单独 `systemctl restart doc-review-worker@1`。
- 沙箱：`NoNewPrivileges`、`PrivateTmp`（LibreOffice 多次启动不互锁）、`ProtectSystem=full`、`ProtectHome=no`（OCR/LibreOffice 要写 home 缓存）、`ReadWritePaths=output temp`。
- 环境：`DATABASE_URL` 通过 `EnvironmentFile=deploy/linux/app.env`（不入库）注入，优先级高于 config.json。`PYTHONUTF8=1`、`OMP_NUM_THREADS=2`、`ARCHIVE_DETECT_QUEUE_MAX=200`。

### 3. nginx（`nginx-doc-review.conf`）
- `client_max_body_size 3g`、`proxy_request_buffering off`、`proxy_read_timeout 600s`。
- `/api/archive-detect/business/batch` 走更严限流（`limit_conn 3` + `limit_req 2r/s burst 10 nodelay`，超出 503）。
- `/uploads/` alias `output/`，`expires 1d`。
- `/healthz` 反代 `:8000/api/healthz`，`proxy_read_timeout 5s`。

### 4. 日常部署流程
```bash
# 本地：构建前端 + rsync 上传
cd e:/qoderproject/20260527
bash deploy/linux/05-upload.sh root@<服务器IP>

# 服务器：依赖/迁移变了才需要
sudo -u docreview bash /opt/doc-review/deploy/linux/02-install-app.sh

# 服务器：重启
sudo systemctl restart doc-review              # 后端代码改动
sudo systemctl restart doc-review-worker@1     # OCR/worker 代码改动（必须单独重启）
sudo systemctl reload nginx                    # 前端 dist 变化
```

### 5. 关键部署约束
- `docx2pdf` 在 Linux 不可用：`template_service._convert_docx_to_pdf` Windows 走 docx2pdf（Word COM），Linux 走 LibreOffice `soffice --headless`。
- `.doc` 抽取优先纯 Python olefile（零系统依赖），失败回退 soffice → antiword。
- OCR 引擎 RapidOCR 模型权重随包内置，无需联网、无 libGL。

## 三、本地开发命令

```bash
# 后端（必须从 backend/ 启动）

# OCR worker（独立进程，必须单独起）

# Windows 一键起后端 + 1 worker
start_backend.bat

# 前端
cd e:/qoderproject/20260527/frontend
npm run dev

# 数据库迁移（alembic.ini 在项目根）
cd e:/qoderproject/20260527
PYTHONIOENCODING=utf-8 PYTHONUTF8=1 ./.venv312/Scripts/python.exe -m alembic upgrade head
```

> **后端和 worker 是两个独立进程，本地开发要分别启动。** 改 OCR/抽取/LLM 代码，uvicorn `--reload` 不重启 worker，必须手动重启 worker。

## 四、启动后台协程（`main.py` startup）
| 协程 | 职责 |
|------|------|
| `_batch_finalize_poll` | 轮询所有文件 done 的批次，生成 overall 总报告 |
| watchdog（`reclaim_expired_leases` 周期调用） | 回收超时 leased 任务（死 worker） |
| `_split_cleanup_loop` | 日志表 30 天 GC + 拆分文件 7 天 TTL + output 目录清理 |
| `file_fetcher.periodic_cleanup_task` | 临时文件延迟清理（Windows WinError 32） |

> **.NET 迁移**：这些后台协程在 .NET 用 `BackgroundService`/`IHostedService` 复刻（finalize 轮询、watchdog、GC、临时文件清理）。
