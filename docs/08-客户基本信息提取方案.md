# 云盘检测 · 客户基本信息提取（doc-extract）实施方案

> 2026-07-23 与主管思路对齐后定稿。
> **注意**：触发方式（worker hook / 回填端点）已被 [09-客户画像-Excel导入方案.md](09-客户画像-Excel导入方案.md) 取代——入口改为 Excel 清单导入的客户画像流水线。本文的**规则子系统**（doc_extract_rules 表、AI 起草→人工审核→激活、extract_doc_fields、归因与只补空写库）仍然有效，已并入 09 方案。

## 1. 背景与目标

主管四步思路：

1. **定基本文件类型**：身份证、户口本、学位证、出生证明——只做这 4 种最常见的。
2. **提取规则 AI 起草 + 人工审核 + 落库**：每种文件提取哪些字段、按什么规则，由 AI 出方案，人工审核后存数据库；规则可查、可改，不写死在代码里。
3. **按库中规则提取**：OCR 识别出文件类型后，读该类型的生效规则提取内容，产出 JSON：{文件类型, 原始内容, 所用规则, 提取结果}。
4. **自动映射入库**：按数据表结构把提取结果映射到对应字段插入数据库。

每一步记日志，出问题可回溯。实施节奏：先把身份证一个类型端到端跑通，再加户口本、学位证。

业务事实（来自 `客户文件信息例子.xlsx`）：一个客户文件夹装全家证件（客户本人 + 配偶 + 子女），文件夹命名不规范（人名文件夹、"户口本2026" 多页 PDF），**必须支持一户多人归属**。

### 已确认的决策

| 决策点 | 结论 |
|---|---|
| 写入策略 | 自动写 `clients`/`family_members`（**只补空不覆盖**）+ 独立结果表全程留痕 |
| 触发方式 | 嵌入业务审核 worker 自动跑 + 手动补跑接口（覆盖历史批次） |
| 规则管理 | DB + REST 接口（Swagger 操作），暂不做前端页 |
| 多人归属 | 按证件号/姓名自动匹配；匹配不到新建 `family_member`（relation='待确认'） |
| 规则冷启 | **纯 AI 起草 + 人工激活**，无手写种子，完整走"AI 出方案、人工审"流程 |

## 2. 关键前提（源码已核实）

1. **脱敏是占位词不是星号**：`redactor.py` 把 18 位身份证整体替换为字面量 `[身份证]`（另有 `[手机号]/[银行卡]/[金额]/[座机]`）。`archive_detect_files.ocr_text` 是脱敏后的——**worker 内提取必须用未脱敏原文**（hook 点在 `_redact_text` 之前拿到的 `text`）；历史回填只有脱敏文本，证件号会抽成 `[身份证]`。masked 判定 = 值含 `*` 或任一 `[…]` 占位词 → 跳过写入，记 `skipped_masked`。
2. `family_members.relation` **NOT NULL**（models.py:111）：新建成员的关系用哨兵值 `'待确认'`，人工后续修。
3. `clients` 表**没有**身份证签发机关/有效期列（只有 passport_* 对应列）：这两字段 `target.column=null`，只抽不写，留在 extracted JSONB。
4. **不新增 worker 状态**：`count_pending_files`/`get_batch_progress` 只认 pending/leased/fetching/ocr/llm 为 running。提取挂在 llm 状态段内执行，这两处过滤器不动。lease 600s 余量充足（+1~2 次 LLM 约 10-30s）。
5. `reuse_ocr_text` 重审路径文本是脱敏的 → masked 规则自然生效，无需特判。
6. `doc_extract_results.extracted` 存**未脱敏**抽取值：与 `ai_api_calls` 原文直存的既定业务决策一致，列 comment 显式声明。
7. `doc_category` 是自由文本（"A-护照"/"G-批复函"），不可靠；只做 `"A-"` 前缀零成本预过滤，类型识别走独立 LLM 白名单判断。

## 3. 数据表（migration 018，`down_revision='4617b534a2d2'`）

### 3.1 `doc_extract_rules`

| 列 | 类型 | 说明 |
|---|---|---|
| id | BigInteger PK | |
| doc_type | String(32) NN | id_card/hukou/degree_cert/birth_cert |
| version | Integer NN | 同 doc_type 内递增 |
| status | String(16) NN default 'draft' | draft/active/disabled，每类型至多一条 active |
| fields | JSONB NN | `[{key,label,description,required,target:{entity,column},example}]`；entity="person" 表示写归因出的人（client 或 member 同名列）；column=null 只抽不写 |
| prompt_extra | Text | 类型级 prompt 注意事项 |
| drafted_by | String(16) NN | ai/human |
| reviewed_by / reviewed_at | String(64)/DateTime | 审核留痕 |
| created_at / updated_at | DateTime NN | |

索引：`ix_doc_extract_rules_type_status(doc_type,status)`；**部分唯一索引** `ux_doc_extract_rules_active ON (doc_type) WHERE status='active'`（`postgresql_where=sa.text(...)`，DB 层兜底单 active）。

### 3.2 `doc_extract_results`（一次提取一行）

| 列 | 类型 | 说明 |
|---|---|---|
| id | BigInteger PK | |
| archive_detect_file_id | Integer NN FK→archive_detect_files.id CASCADE | 来源文件行 |
| batch_id | String(40) NN | |
| file_id | String(200) | 业务文件编码 |

## 4. 文件级改动（按 slice，每个 slice 独立可验证）

### (a) 规则存储 + 规则端点 + AI 起草 → Swagger 走通 draft→review→activate

- **`migrations/versions/018_doc_extract.py`**（新）：建两表+索引，无种子数据；仿 017 风格，全列中文 comment。
- **`backend/db/models.py`**：`DocExtractRule`/`DocExtractResult` 两类（放 AiApiCall 后）。
- **`backend/db/doc_extract_crud.py`**（新，仿 `ai_api_call_crud.py`）：
  - 规则：`create_rule`(version=max+1) / `get_rule` / `get_active_rule` / `list_rules` / `update_rule_draft`(非 draft 抛 ValueError→端点 409) / `activate_rule`(单事务：同类型其他 active→disabled，本行 active+reviewed_at) / `disable_rule`
  - 结果：`insert_result` / `list_results` / `get_result`
  - 归因+写库（import `client_profile_crud._parse_date/_clean_str` 复用，不复制）：
    - `find_person_match(client_id, id_number, name)`：clients.id_number → members.id_number → clients.name → members.name，返回 `{entity:client|member|None, row_id, matched_by}`
    - `apply_extracted_fields(client_id, match, field_items)`：match 为 None 且有 name → 新建 FamilyMember(relation='待确认')；只补空；Date 列 `_parse_date`；返回 `{mapped, write_stats}`
- **`backend/llm_service.py`** 末尾追加（均走 `_call_llm`，自动记 ai_api_calls，worker 线程安全）：
  - `draft_extract_rule(doc_type, target_columns, **context)`：给中文类型名+可写列清单，返回 `{fields, prompt_extra}`；operation="draft_extract_rule"
  - `recognize_doc_type(text_head, **context)`：截 2000 字，白名单 4 类+other，返回 `{doc_type,confidence,_fallback}`；失败→other 不抛（宁漏不误），仿 `detect_large_table_doc`；max_retries=2
  - `extract_doc_fields(text, rule, **context)`：30000 字 head+tail 截断；prompt 由 rule.fields+prompt_extra 拼；返回 `{fields:{key:value}}`；失败抛（service 统一 catch）
- **`backend/main.py`** 端点（tags=["信息提取"]）：
  - `POST /api/doc-extract/rules/draft {doc_type}`（校验白名单 400）
  - `GET /api/doc-extract/rules`、`GET /api/doc-extract/rules/{id}`
  - `PUT /api/doc-extract/rules/{id}`（仅 draft，409）
  - `POST /api/doc-extract/rules/{id}/activate`、`POST /api/doc-extract/rules/{id}/disable`

### (b) 识别+提取 + service + worker 钩子 → 真实批次身份证跑出 done 行

- **`backend/db/archive_detect_crud.py` `get_batch_context`（:1262)**：select 加 `Client.id.label("client_id")`（join 已存在，一行改动）；quick 历史批次得 None → skip。
- **`backend/doc_extract_service.py`**（新）：
  - 常量：`PREFILTER_CATEGORY_PREFIX="A-"`、`RECOGNIZE_MIN_CONFIDENCE=60`、`_MASKED_TOKENS=("[身份证]","[手机号]","[银行卡]","[金额]","[座机]")`
  - 纯函数：`_is_masked(v)`、`_valid_id_number(v)`（17 位数字+数字/X）
  - `async maybe_extract_for_file(*, file_db_id, batch_id, file_id, raw_text, doc_category, batch_ctx)`，**全 try/except 永不抛**：
    client_id 空→skip(no_client)；doc_category 非空且非 "A-" 前缀→静默返回（零成本预过滤）；to_thread recognize→非 4 类/confidence<60/_fallback→skip；无 active 规则→写 skipped(no_active_rule) 行；to_thread extract；字段清洗（masked→skipped_masked、id_number 非法→skipped_invalid）；find_person_match→apply_extracted_fields；insert_result(done)+`extract.done` 事件；异常→insert_result(error)+`extract.error`，吞掉
- **`backend/worker_runner.py`** hook（精确位置：`ocr_text_redacted = _redact_text(text)` 之后、`# 4) 写终态 done` 之前，约 :158-160）：

  ```python
  # 3.5) 证件信息提取(用未脱敏原文;失败不影响归档判定)
  try:
      import doc_extract_service
      await doc_extract_service.maybe_extract_for_file(
          file_db_id=file_db_id, batch_id=batch_id, file_id=task.get("file_id"),
          raw_text=text, doc_category=verdict.get("doc_category"), batch_ctx=batch_ctx)
  except Exception as _ex:
      print(f"[{worker_id}:{batch_id}:{idx}] 信息提取异常(已忽略): {_ex}")
  ```

  用 raw text 是关键；`archive_detect_files` 与 `update_file_done` payload 零改动。
- **`backend/event_service.py`**：`CATEGORY_EXTRACT_DONE/ERROR/SKIP = "extract.done"/"extract.error"/"extract.skip"`。

### (c) 归因+写库接通 → 单测过 + 重跑批次验证补空

- 归因顺序：干净 id_number→clients→members；name 精确匹配→clients→members；都不中有 name→新建 member('待确认')；连 name 都没有→skipped(no_person)
- 只补空语义同 `apply_profile_facts`；relation 一律中文值（不引入英文枚举坑）；member 表无 hukou_address/ethnicity 列，归因到 member 时这两字段记 unmapped 不炸
- 同批多张身份证（全家）各自独立归因，id_number 区分人

### (d) 回填 + 结果查询 → 历史批次验证 skipped_masked

- `POST /api/doc-extract/run`：body 恰好一个选择器（batch_id | client_id | file_row_ids，400）+ 可选 doc_type（给了则跳过 recognize 直接查规则，省一次 LLM）；500 行硬上限；`asyncio.create_task(run_backfill)` 返回 task_id
- `GET /api/doc-extract/run/{task_id}`：进程内 dict 进度（MVP ops 工具，重启丢状态可接受）
- `GET /api/doc-extract/results`（batch_id/file_id/doc_type/status 筛选+分页）、`GET /api/doc-extract/results/{id}`（extracted/mapped 全文）
- 回填走同一 `maybe_extract_for_file`，raw_text 实参=已脱敏 ocr_text → masked 规则生效：证件号写不进，姓名/性别/出生日期/民族/住址仍可补

### (e) 测试 + runbook

- `tests/test_doc_extract_rules.py`（assert 脚本风格，仿 test_event_service.py）：version 自增、activate 单 active、draft 才可改、disable、get_active_rule；测后清理
- `tests/test_doc_extract_mapping.py`：id_number 命中 client 只补空 / name 命中 member / 无命中新建'待确认' / `[身份证]`→skipped_masked / 非空字段 skipped_filled / birth_date 转 Date；附 _is_masked/_valid_id_number 纯函数测试
- （可选）`tests/smoke/test_doc_extract_e2e.py`：真 LLM 手动跑

## 5. 验证 runbook（端到端）

1. `alembic upgrade head` → 两表+部分唯一索引就位
2. Swagger：`POST /api/doc-extract/rules/draft {doc_type:"id_card"}` → 审 draft（必要时 PUT 改 fields）→ `activate` → `GET /rules?doc_type=id_card&status=active` 确认唯一
3. 起 backend + worker，用含全家身份证的批次提交业务审核 → 查 `doc_extract_results`（status=done、extracted 有值）、`ai_api_calls`（operation=recognize_doc_type/extract_doc_fields）、`clients`/`family_members` 补空（客户本人写 client，配偶/子女按证件号新建或补 member）
4. 历史批次 `POST /api/doc-extract/run {batch_id}` → mapped 中见 `skipped_masked`；`GET /results` 筛选验证
5. 两个单测脚本通过；故意改坏规则 JSON → error 行 + `extract.error` 事件，批次判定不受影响

## 6. 明确不做（YAGNI）

- 不做前端规则管理页（DB+Swagger 操作）；不加 worker 新状态；不改 `archive_detect_files`；不加 clients 新列（签发机关/有效期只抽不写）；回填任务不建任务表；户口本多成员抽取不做（MVP 按单人，prompt_extra 注明，上线后迭代）

## 7. 扩展路径（后续类型零重构）

hukou/degree_cert/birth_cert 只需 `draft → 人工审 → activate` 对应规则即可上线：`recognize_doc_type` 白名单已含 4 类，service/归因/写库逻辑与类型无关。规则要调整时 draft 新版本（version+1）再 activate，旧版本自动 disabled，历史结果里 rule_id/rule_version 可回溯当时用的是哪套规则。
