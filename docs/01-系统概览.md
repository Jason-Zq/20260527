# 01 · 系统概览

## 1. 项目定位

智能文档审核工作台，面向移民 / 售后客户材料处理。当前主线是**文件留底检测 / 业务审核**，同时保留材料解析、Word 模板填写、PDF 拆分、URL 文件摘要等能力。

## 2. 六条业务线

| # | 业务线 | 简述 | 关键入口 |
|---|--------|------|---------|
| 1 | **文件留底检测 / 业务审核**（主线） | 业务方传入 客户+项目+进展+文件URL 列表；后端 OCR/文本抽取 + LLM 按公司留底分类体系判定，持久化单文件结果、脱敏 OCR 文本、批次总体报告，支持同 `(progress_id, file_id)` 历史结果复用 | `POST /api/archive-detect/business/batch` |
| 2 | **AI 材料解析** | 上传 PDF/图片 → OCR + LLM 提取结构化字段 → 人工复核 → 归档到客户档案 | `POST /api/upload` |
| 3 | **客户档案结构化生成** | 从留底检测完成的 OCR 文件中批量抽取客户/家庭/资产事实，写入客户档案（**只补空，不覆盖人工数据**） | `POST /api/client-profile/generate/{client_id}` |
| 4 | **Word 模板填写** | 上传 docx 模板 → 扫描占位符/锚点 → 选客户 → 从档案填值 → 输出 docx/PDF | `POST /api/templates/parse` |
| 5 | **PDF 拆分** | 上传多证件合并 PDF → 全页 OCR + LLM 判断页边界 → 按证件类型拆为独立 PDF | `POST /api/split` |
| 6 | **URL 文件摘要** | 输入文件 URL + 进展名 → 下载/OCR/抽文本 → LLM 摘要与相关性判断 | `POST /api/file-summary` |

外加：客户档案管理（clients/family/assets）、检测批次管理后台、销售线索（子女年龄）、可观测性（事件流/请求记录/外部接口记录/AI 调用记录）。

## 3. 总体架构

```text
┌─────────────────────────────────────────────────────────────┐
│ 前端  Vue 3 + Element Plus + Vite + vue-router(hash)          │
│  router.js / api.js(axios) / components/*.vue                 │
└───────────────────────────┬─────────────────────────────────┘
                            │ HTTP /api/*
┌───────────────────────────▼─────────────────────────────────┐
│ 后端主进程  FastAPI + SQLAlchemy 2 async + Alembic            │
│  main.py — 路由聚合 / startup-shutdown / 内存态轮询缓存        │
│  只接 HTTP、写 DB、跑 finalize 轮询 + watchdog                │
│  （uvicorn --workers=1 不可改：主进程内存态缓存不可分裂）      │
└──────┬───────────────────────────────────┬──────────────────┘
       │ 写 DB(pending 任务)                │ 读 DB(轮询结果)
┌──────▼────────────────┐          ┌────────▼──────────────────┐
│ PostgreSQL            │◄────────►│ OCR Worker(独立进程,可多起) │
│ archive_detect_files  │ SKIP     │ worker_runner.py           │
│ 等 19 张表            │ LOCKED   │ fetch→OCR→LLM→写终态        │
└───────────────────────┘          └────────┬───────────────────┘
                                            │ 调用
                          ┌──────────────────┼──────────────────┐
                          ▼                  ▼                  ▼
                   RapidOCR 引擎      LLM(OpenAI 兼容)   业务方文件服务
                   (onnxruntime)      config.json 驱动   getFileDownloadUrl
```

**关键架构约束（当前系统）**：

- **业务审核 = DB 队列 + 多进程 worker（方案二 2b）**：主进程（uvicorn）只接 HTTP、写 DB、跑 finalize 轮询 + watchdog；OCR/LLM 由独立的 `worker_runner.py` 进程通过 `SELECT FOR UPDATE SKIP LOCKED` 抢 `archive_detect_files` 的 pending 任务。状态全落 DB，进程重启不丢任务。
- **uvicorn `--workers=1` 不能改**：主进程保留内存态 `_batch_status` 作前端轮询 fast-path；多 uvicorn worker 会让缓存分裂。并发靠多起 `worker_runner` 进程。
- **OCR worker 数 = 起几个 `worker_runner` 进程**。4C/8G 小机器保持 1 个 worker，OCR 串行，稳定优先。
- **后端和 worker 是两个独立进程**，本地/服务器都要分别启动。改 OCR/抽取/LLM 代码必须手动重启 worker。

## 4. 技术栈

### 后端（Python）
- **Web 框架**：FastAPI
- **ORM**：SQLAlchemy 2 async（asyncpg）+ 同步引擎（psycopg2，供 Alembic 和 worker 线程日志）
- **迁移**：Alembic
- **OCR 引擎**：RapidOCR（onnxruntime，CPU），**不是 PaddleOCR**。模型权重随包内置，无需联网、无 libGL 依赖
- **PDF 处理**：pdfplumber（文字型抽取 + 类型判断）、pypdfium2（渲染成图）
- **文档抽取**：python-docx（.docx）、openpyxl（.xlsx）、python-pptx（.pptx）、olefile（.doc 纯 Python 解析）
- **LLM**：openai SDK（OpenAI 兼容接口），模型 ID 由 config.json 驱动
- **HTTP 客户端**：httpx（下载 URL/OSS、LLM 超时控制）
- **Word 渲染**：docx2pdf（Windows/Word COM）/ LibreOffice soffice（Linux headless）

### 前端
- Vue 3 + Element Plus + Vite + vue-router（hash 模式）
- axios 封装在 `frontend/src/api.js`

### 数据库
- PostgreSQL（生产 `8.138.111.12:5432/doc_review`）
- JSONB 用于 `extracted_fields`、`key_points`、`placeholders`、`ranges`、`context` 等

## 5. 目录结构

```text

  main.py                     FastAPI 入口 + 全部路由（无 APIRouter，集中式）
  worker_runner.py            独立 worker 进程：SKIP LOCKED 抢任务 → OCR → LLM → 写终态
  archive_detect_service.py   文件留底检测编排（提交入队、增量复用、watchdog、finalize）
  llm_service.py              LLM 调用封装与各业务 prompt（OpenAI 兼容）
  ocr_service.py              RapidOCR 引擎封装 + PDF/图片 OCR（run_ocr 统一入口）
  text_extractor.py           PDF/图片/docx/doc/xls/pptx 统一文本抽取
  split_ocr_service.py        PDF 拆分专用全页 OCR
  split_service.py            PDF 页范围规整与拆分
  template_service.py         Word 模板解析、锚点扫描、渲染
  client_profile_service.py   客户档案结构化生成编排（只补空不覆盖）
  file_fetcher.py             httpx 下载 URL/OSS + URL 刷新 + 延迟清理
  redactor.py                 PII 脱敏（金额/手机号/身份证/银行卡/座机）
  event_service.py            业务事件流写 system_events
  middleware/
    request_log_middleware.py 纯 ASGI 中间件，记 POST /business/batch 请求体
  db/
    engine.py                 async_engine(asyncpg) + sync_engine(psycopg2)
    models.py                 全部 ORM 模型
    *_crud.py                 各表 CRUD（archive_detect_crud 是队列状态机核心）

frontend/
  src/router.js               路由表
  src/api.js                  axios API 封装
  src/components/*.vue         各业务页面

migrations/versions/          Alembic 迁移（001 → 017_ai_api_calls）
deploy/linux/                 systemd + nginx 部署方案
config.json                   DB + LLM + OCR/文档类型 + 文件服务配置
output/                       静态挂载为 /uploads/，保存 PNG/PDF/DOCX 产物

```

## 6. 配置文件（config.json）

```json
{
  "database": {"host": "...", "port": 5432, "user": "postgres", "password": "...", "dbname": "doc_review"},
  "llm": {"api_key": "...", "base_url": "https://.../api/v3", "model": "...", "temperature": 0.1},
  "file_url_service": {
    "enabled": true,
    "base_url": "https://restful.huanqiuyimin.com/Cloud/getFileDownloadUrl",
    "default_type": "preview",
    "usr_login": "Jason邹启", "operation_user": "Jason邹启", "url": "batch",
    "timeout_sec": 20
  },
  "max_ocr_pages": 5,
  "document_types": ["身份证", "护照", "..."]
}
```

- **DB 连接优先用 `DATABASE_URL` 环境变量**，否则回退 config.json。
- LLM 走 OpenAI 兼容接口，模型 ID 完全由 config.json 驱动。
- `max_ocr_pages` 仅影响 AI 材料解析 `/api/upload`；文件留底检测走全页 OCR（大文件有 early-exit 采样）。
- `document_types` 用于证件解析和 PDF 拆分页分类；文件留底检测已改用 `llm_service.py` 硬编码的公司售后留底分类体系。
- `file_url_service`：业务方 `getFileDownloadUrl` 刷新过期 URL 的身份参数。
