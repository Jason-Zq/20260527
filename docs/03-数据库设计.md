# 03 · 数据库设计

> 数据库：PostgreSQL（`doc_review`）。ORM：`backend/db/models.py`。迁移：`migrations/versions/`（001 → 022）。当前 head = `022_project_cases`（画像按项目多案件；完整迁移链见 §8）。
>
> 重构到 .NET：**保留 PostgreSQL，表结构基本不变**，用 EF Core / Npgsql 接入。JSONB 列在 EF Core 中用 `jsonb` 映射。

## 0. 连接与引擎

### 0.1 连接配置（`backend/db/engine.py` `_build_dsn`）
优先级：
1. **环境变量 `DATABASE_URL`**（整段 DSN，12-factor 友好，systemd/Docker 用）。`postgresql://` 前缀会按目标驱动重写为 `+asyncpg` 或 `+psycopg2`。
2. **`config.json` 的 `database` 段**（`host/port/user/password/dbname`）。

### 0.2 双引擎（asyncpg + psycopg2）
| 引擎 | 驱动 | 用途 |
|------|------|------|
| `async_engine` / `async_session_maker` | asyncpg | FastAPI 运行时**绝大多数**读写。pool_size=10, max_overflow=20, pool_pre_ping, pool_recycle=1800，强制 `client_encoding=utf8` |
| `sync_engine` / `SyncSession` | psycopg2 | Alembic 迁移；**worker 线程里的同步日志写入**（无 async loop 可用的场景） |

**用 psycopg2 同步写入的路径**（worker 线程跨 loop 用 async 引擎会报 "attached to a different loop"）：
- `ai_api_call_crud.insert_ai_api_call_sync()`
- `external_api_log_crud.insert_external_api_log_sync()`

> **.NET 迁移提示**：.NET 天然多线程，用 Npgsql 连接池即可，不需要区分同步/异步双引擎。此双引擎是 Python async 生态的历史包袱。

### 0.3 GC / TTL 清理（`main.py` `_split_cleanup_loop`）
| 表 | 保留期 | 依据列 |
|----|--------|--------|
| `system_events` | 30 天 | occurred_at |
| `api_request_logs` | 30 天 | created_at |
| `external_api_logs` | 30 天 | created_at |
| `ai_api_calls` | 30 天 | created_at |
| `split_tasks`（仅物理文件） | 7 天 | 只删 output/ 文件，DB 行保留置 `files_cleaned=true` |

其余业务表（clients/family/assets/documents/client_info/summaries/templates/template_fills/archive_detect_*/client_profile_generation_tasks）**无自动 GC**，长期保留。

## 2. 核心客户档案表

### 2.1 `clients` — 客户主表（~33 字段）
主键 `id`（自增）。移民客户的身份/联系/护照/教育/工作/婚姻/业务标签。

关键列：`client_code` String(30) **unique**（业务方稳定客户编码）、`name`(非空)、`name_en`/`former_name`、`gender`、`birth_date`、`nationality`、`id_number` **unique**、`passport_no`、`passport_expiry_date`(索引)、教育字段（school_name/major/degree/graduation_date/…）、工作字段（company_name/position/monthly_salary Numeric(12,2)/…）、婚姻字段、`visa_type`(索引，业务类型标签)、`consultant`、`notes`、`created_at`/`updated_at`。

索引：`uq_clients_client_code`(unique)、id_number unique、`ix_clients_passport_expiry`、`ix_clients_visa_type`。
关系：一对多 documents/client_info/family_members(cascade)/assets(cascade)；被 progress、profile_tasks 引用。

### 2.2 `family_members` — 家庭成员（配偶/子女/父母/紧急联系人）
主键 `id`。FK `client_id → clients.id`（CASCADE，非空）。
关键列：`relation` String(20)(非空)、`name`(非空)、基本信息（name_en/gender/birth_date/nationality/id_number/phone）、POA 必需字段（passport_no/email/current_address/company_name/position）、配偶教育 7 列、子女出生 3 列（birth_cert_no/birth_hospital/birth_place）、`will_accompany` Bool(是否随行)、notes。
索引：`ix_family_members_client_relation (client_id, relation)`。
只读销售视图：`sales_crud.list_child_age_leads` JOIN clients + family_members 算子女年龄。

### 2.3 `assets` — 资产（房产/存款/流水/股票/车辆/其他共表）
主键 `id`。FK `client_id → clients.id`（CASCADE，非空）。
关键列：`asset_type` String(20)(非空)、asset_name/owner_name/co_owners、`value_amount` Numeric(18,2)、currency、certificate_no；房产专用（location_address/area_sqm/usage_type/acquired_date）；银行专用（bank_name/account_no/period_start/period_end/frozen_until）；notes。
索引：`ix_assets_client_type (client_id, asset_type)`。

### 2.4 `documents` — 文档/解析记录（证件解析 OCR→LLM 流水线）
主键 `id`。FK `client_id → clients.id`（nullable）。
关键列：`task_id` String(200) **unique 非空**（对应 output/ 目录名）、filename(非空)、doc_type、file_path、`ocr_text` Text、`extracted_fields` **JSONB**、confidence_avg Float、reviewed Bool、`status` String(20) default 'ocr'（**ocr/llm/done/error**）、error_msg、created_at。
索引：`ix_documents_extracted_fields`(**GIN**)、`ix_documents_status`、`ix_documents_created_at`。

### 2.5 `client_info` — 客户关键信息 KV 兜底表
主键 `id`。FK `client_id`(非空)、`source_doc_id → documents.id`(可空)。
关键列：`info_key` String(100)(非空)、info_value Text、valid_from/`valid_until` Date、confirmed Bool。
索引：`ix_client_info_valid_until`、`ix_client_info_client_key (client_id, info_key)`。

## 3. 模板与拆分

### 3.1 `templates` — Word 模板
主键 `id`。列：name(非空)、filename、file_path、`placeholders` **JSONB**（`[{id,description,original_text}]`）、created_by、created_at/updated_at。一对多 template_fills(cascade)。

### 3.2 `template_fills` — 模板填充历史（兼作 (template_id,client_id) 映射缓存）
主键 `id`。FK `template_id`(非空)、`client_id`(可空)。列：`placeholder_values` **JSONB**（`{strN: value}` 快照）、output_pdf、created_at。索引 `ix_template_fills_template`/`ix_template_fills_client`。

### 3.3 `split_tasks` — PDF 拆分任务
**主键 `task_id`** String(200)（对应 output/ 目录名，非自增）。列：filename(非空)、total_pages、`status` String(20) default 'ocr'（**ocr|llm|splitting|done|error**）、error Text、`ranges` **JSONB**、duration_sec Float、`files_cleaned` Bool default false、created_at/updated_at。索引 `ix_split_tasks_status`/`ix_split_tasks_created_at`。无 FK。

## 5. 文件留底检测家族（archive_detect_*）

> 这是主线业务的核心，重构时最需精确复刻。CRUD 状态机核心在 `archive_detect_crud.py`。

### 5.1 `archive_detect_progress` — 进展包（稳定业务实体）
一个进展包 = 一个客户的一个项目详情的一个进展。主键 `id`。FK `client_id`(非空)。
列：handler、project_name/project_code、project_detail_name/project_detail_code、`progress_oid` String(100)(非空，业务方标识)、progress_name。
**唯一约束**：`ux_archive_detect_progress_client_oid (client_id, progress_oid)` — 同客户内 OID 不重。
一对多 → batches/files/folder_summaries。

### 5.2 `archive_detect_batches` — 批次（一次提交动作）
**主键 `batch_id`** String(40)。
列：`user_prompt` Text(非空，留底判定标准/criteria，拼进 LLM prompt)、`source_kind` String(10)(非空，**batch|recheck**；历史保留 upload/url)、`stage` String(20)(**pre_submit|post_submit**，worker 读取传 LLM)、total_files(1-20)、done_files default 0、`status` String(20) default 'running'（**running|done|error**）、error。
业务快照列（仅业务模式有值）：`progress_id` FK → progress.id、`overall_verdict` String(20)(match|partial|mismatch)、overall_score Int(0-100)、overall_reason Text。
索引：`ix_archive_detect_batches_created_at`/`ix_archive_detect_batches_progress`。一对多 files(cascade, order_by idx)。

### 5.3 `archive_detect_files` — 单文件结果（**核心状态机表**）
主键 `id`。FK `batch_id → batches.batch_id`(CASCADE,非空)、`progress_id → progress.id`(可空)。

**字段分组：**
- 顺序/去重：`idx` Int(非空，batch 内 0-based)、`file_id` String(200)(调用方文件标识=增量复用 key)、`version` Int default 1、content_sha256 String(64)(已建列当前不写值)、`deleted` Bool default false(软删)
- 来源：source_url Text、`local_path` Text(upload 模式残留，现停用)、filename、mime_type
- 抽取产物：page_count、char_count、`ocr_text` Text（**已脱敏**）
- LLM 判定：is_archival Bool、`confidence` Int(旧字段=match_score 语义)、`match_score` Int(0-100)、`verdict` String(20)、reason Text(脱敏)、`key_points` **JSONB**(脱敏)、doc_category

**关键状态机字段：**

| 字段 | 取值 | 说明 |
|------|------|------|
| `status` | `pending → leased → fetching → ocr → llm → done`/`error` | 见下方状态机 |
| `verdict` | `match`/`partial`/`mismatch`/**`no_text`** | 单文件业务结论。`no_text`=OCR/抽取后无有效文字，标 done 不算失败、不参与总体判定 |
| `reuse_ocr_text` | Text | 重审/重跑入队时预填的源 OCR 文本；**worker 抢到后若非空则跳过下载+OCR，直接跑 LLM** |
| `worker_lease_until` | DateTime | worker 抢任务后写 `now()+600s`；watchdog 扫过期 leased 行回收 |
| `retry_count` | Int default 0 | 失败重试计数，`>=1`(MAX_RETRY_COUNT) 不再 retry，置 error |

**status 状态机：**
```text
pending  ── worker claim_one_pending_file (UPDATE WHERE status='pending' FOR UPDATE SKIP LOCKED) ──► leased
leased   ── update_file_intermediate_status(续租) ──► fetching ──► ocr ──► llm
llm      ── update_file_done ──► done          （成功终态）
任何步骤异常 ── update_file_error ──► error     （失败终态）
leased 超时 ── watchdog reclaim_expired_leases ──► pending(retry+1) 或 error(超重试)
reuse_ocr_text 非空 ── worker 跳过 fetching/ocr ──► 直接 llm
```

索引：`ix_archive_detect_files_batch_id`；`ux_archive_detect_files_batch_idx (batch_id, idx)` unique；`ix_archive_detect_files_progress`；`ix_archive_detect_files_fileid_version (progress_id, file_id, version)`；`ix_archive_detect_files_fileid_hash`；`ix_archive_detect_files_deleted`；两个 **partial index**：`ix_archive_detect_files_pending (WHERE status='pending')`(worker 抢任务)、`ix_archive_detect_files_leased_until (WHERE status='leased')`(watchdog 回收)。

> **.NET 迁移提示**：`SELECT ... FOR UPDATE SKIP LOCKED` 抢任务模式 Npgsql/EF Core 也支持（`FromSqlRaw` 或原生 SQL）。两个 partial index 建议保留。

### 5.4 `archive_detect_folder_summaries` — 进展包维度滚动总报告（多版本）
主键 `id`。FK `progress_id`(CASCADE,非空)。列：`version` Int(非空)、criteria Text、`summary` **JSONB**、file_count Int、created_at。
唯一约束 `ux_archive_detect_summaries_progress_version (progress_id, version)`。
> **注意**：此表已建但当前不写入，是后续阶段功能，不要误以为已启用。

## 6. 客户档案结构化生成

### 6.1 `client_profile_generation_tasks`
基于 `archive_detect_files.ocr_text` 生成并写入客户档案。主键 `id`。FK `client_id`(CASCADE,非空)。
列：`status` String(20) default 'running'（**running|done|error**）、`source_file_ids` **JSONB**、`source_files_snapshot` **JSONB**、source_file_count Int、`extracted_summary` **JSONB**、`created_count` **JSONB**、error、created_at/updated_at。
CRUD `client_profile_crud.apply_profile_facts`：抽取结果**只补空字段、不覆盖人工数据**写入 clients/family_members/assets/client_info。

## 7. 日志 / 审计表（均 30 天 GC）

### 7.1 `system_events` — 业务事件流
主键 `id` BigInteger。列：`occurred_at`(非空)、`severity` String(10)(**info|warn|error|critical**，CHECK 约束)、`category` String(40)(非空)、`message` String(500)(非空)、`context` **JSONB**。
索引：`ix_system_events_occurred (DESC)`、severity/category 组合索引，外加表达式 partial 索引 `ON ((context->>'batch_id')) WHERE context ? 'batch_id'`。

### 7.2 `api_request_logs` — API 请求记录（中间件写入）
主键 `id` BigInteger。列：created_at、`source` String(20)(business/admin/poll/other)、`method`、`path` String(300)、client_ip、`request_body` **JSONB**、response_status、elapsed_ms。
> ⚠️ **潜在漂移**：`source` 列在 ORM 模型中存在，但迁移 `014` 未创建它。若从零按迁移建库，该列会缺失导致写入报错。**.NET 迁移时建 schema 需确认并补上此列。**

### 7.3 `external_api_logs` — 出站外部接口记录
主键 `id` BigInteger。列：created_at、`service` String(20)(**refresh_url|llm**)、url Text、`request_params` **JSONB**、`response_summary` **JSONB**、`status` String(10)(**ok|error**)、error_msg、elapsed_ms、batch_id、file_id。

### 7.4 `ai_api_calls` — AI/LLM 调用记录（当前 head 迁移新增）
主键 `id` BigInteger。列：created_at、operation String(64)、model String(64)、prompt Text（写库前 `_clean_text` 去 NUL/控制字符 + 截断 50000 字）、response_raw Text（同样清洗）、`status` String(10)(**ok|error**)、error_msg(截断 2000 字)、elapsed_ms、batch_id、file_id、client_code、task_id。
索引：created_at + operation/model/batch_id/file_id/client_code/status 各建 `(col, created_at DESC)`。
> **重要**：prompt/response **原文直存未脱敏**（业务决策，含脱敏前 OCR）。入库前统一去 NUL/控制字符（PG text 列不接受 `0x00`）。
