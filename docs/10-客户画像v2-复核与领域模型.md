# 客户画像 v2 · 独立领域模型 + 复核闭环 + 质量评级 + 原件在线查看

> 2026-07-24 定稿并实施（migration 019）。承接 [09-客户画像-Excel导入方案.md](09-客户画像-Excel导入方案.md) 的流水线，按行业最佳实践重构档案层。
> **两条不变原则**：文件 OCR 信息保存（原文）；AI 大模型外部请求日志（ai_api_calls）全量保存。

## 1. 设计原则

1. **什么都可以改，受影响就新建**：画像系统自建 `profile_*` 领域模型，**不再写入 clients/family_members**（老表留给 POA 模板/老档案页，仅 `legacy_client_id` 软关联，互不影响）。
2. **实体为中心，不是文件为中心**：档案的主角是「人」和「家庭」，文件只是证据。
3. **字段级证据链**：每个档案字段都带 值/可信度层/来源文件/确认状态。
4. **自报 vs 核证分层（declared vs verified）**：KYC 表自报为 declared，官方证件为 verified；verified 不覆盖人工、declared 不覆盖 verified。
5. **人工主权**：复核修正（corrected）/确认（confirmed）的字段，AI 永不再覆盖。
6. **复核有轻重缓急**：纯规则质量评级（不调 LLM），待复核队列按质量分升序。

## 2. 数据模型（migration 019）

| 表 | 作用 | 关键列 |
|---|---|---|
| `profile_households` | 家庭/客户组 | name, legacy_client_id（软关联）, main_person_id |
| `profile_persons` | 人（骨架） | household_id, name, relation_to_main（户主/配偶/子/女/待确认）, is_main, avatar_file_id |
| `profile_person_fields` | **字段级档案+证据链** | person_id+field 唯一, value, **layer**(verified/declared), source_file_id, source_result_id, **status**(ai/confirmed/corrected), updated_by |
| `profile_assets` | 资产 | household_id, owner_person_id, asset_type, name, attrs JSONB, source_file_id |
| `profile_cases` | 案件+时间线(一个售后项目=一个案件) | household_id, case_type, status, milestones JSONB, affter_entryoid(路由键,NULL=默认案件), projectno/projectname/projectno_detailed/projectname_detailed/project_created_at |

`customer_files` 加列：`local_path`（原件落盘 output/customer_files/）、`file_keep_until`（30 天 GC）、`review_status`(none/needs_review/reviewed)、`review_reason`、`quality_score`。
`doc_extract_results` 加列：`review_status`(pending/confirmed/corrected/dismissed)、`corrected` JSONB、`reviewed_by/at`。
`profile_import_tasks` 加列：`household_id`、`needs_review_count`。

**字段写入语义**（`profile_crud.apply_extracted_fields_v2`）：
- 已有字段 status ∈ {confirmed, corrected} → `skipped_confirmed`（人工不动）
- 已有 verified、新值 declared → `skipped_layer`
- 同值 → `skipped_same`；其余 AI 可更新 AI 值（written/updated）
- 归因：household 内证件号（走 person_fields）→ 姓名（persons.name），无命中新建 person（relation=待确认）
- 复核修正（`correct_person_field`）永远覆盖 → status='corrected'；空值=清除字段

## 3. 质量评级（review_service，纯规则）

| 判定 | 分 | 原因 |
|---|---|---|
| 无文本（非证件照文件夹） | 0 | no_text |
| OCR 乱码（怪字符〓/Φ/□/■ >8% 直接判；或 CJK<35% 且 >3%） | 10 | garbled |
| 提取异常 | 15 | extract_error |
| no_person（无法归属） | 20 | no_person |
| 文本 <30 字 | 30 | ocr_short |
| 证件号被脱敏（复用文本） | 40 | masked_id |
| LLM 分类置信 <60 | 50 | low_confidence |
| 其余 | 100 | 无待复核 |

证件照文件夹（含"证件照"）无文本是预期，不判复核。任务级 `needs_review_count` 驱动前端红色横幅。

## 4. 原件留存与在线查看

- 导入下载的原件从 temp 移存 `output/customer_files/<file_code>_<文件名>`，`file_keep_until = now+30d`
- `GET /api/profile/files/{id}/raw`：本地有→FileResponse；已 GC→`refresh_download_url` 重下→落盘顺延 30 天
- `GET /api/profile/files/{id}/preview-pdf`(2026-07-28)：Office 原件(doc/docx/xls/xlsx/ppt/pptx)soffice 按需转 PDF,缓存 `output/customer_files/previews/{file_id}.pdf`;无 LibreOffice 返回 501,前端回落"不支持在线预览"
- GC 挂 `_split_cleanup_loop`：到期删磁盘原件 + 清 local_path（**DB 记录与 OCR 文本永久保留**）
- 前端 axios blob（带 Bearer）→ objectURL：图片内联显示，PDF/Office(转 PDF) iframe

## 5. 复核闭环

端点（tag「复核」）：
- `GET /api/review/files`：队列（按 quality_score 升序，可筛 task/client/reason）
- `GET /api/review/files/{id}`：文件+OCR+最近提取结果+家庭成员选项
- `POST .../confirm`：确认无误 → file reviewed + result confirmed
- `POST .../correct`：修正字段（永远覆盖）+ 可选改归属人/新建人/修正关系 → result corrected 留痕
- `POST .../dismiss`：忽略 → result dismissed

前端复核抽屉三栏：原件 | OCR 文本 | 归属选择+字段表单+[确认无误/保存修正/忽略]，处理完自动跳下一条。**抽屉已抽为共享组件 `ReviewDrawer.vue`**(prop `importTaskId` 可选,不传即跨任务全局队列;`@done` 通知父级刷新):画像弹窗传入当前任务 id,**全局复核中心页 `/review-center`(ReviewCenterPage)** 不传——跨任务/跨家庭队列(质量分升序,客户名+原因筛选,行自带 client_name),导航栏「复核中心」入口(§9.6)。
